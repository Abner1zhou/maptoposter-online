## Project Overview

MapPoster Online is a browser-based app that turns cities into artistic map posters. It runs entirely client-side — no server backend. Map data comes from OpenStreetMap (Overpass API), rendering is done by a Rust/WASM engine (tiny-skia), and the UI is React 19 + TypeScript.

## Commands

```bash
bun install              # Install dependencies
bun run dev              # Start dev server (http://localhost:5173)
bun run build            # Production build (compiles i18n + TypeScript + Vite)
bun run build:wasm       # Rebuild Rust → WASM (requires Rust + wasm-pack, runs build.ps1 via PowerShell)
bun run preview          # Preview production build
bun run lint             # Run oxlint
bun run fix              # Format (oxfmt) + lint auto-fix (oxlint --fix)
bun run format           # Format with oxfmt
bun run format:check     # Check formatting without writing
```

No test runner is configured as a script. Test files exist (`*.test.ts`) but use Bun's built-in test runner directly (`bun test <file>`).

## Architecture

### Two-Worker Pipeline

All heavy computation runs off the main thread via two Web Workers:

1. **Data Worker** (`src/data-worker.ts`) — Fetches map data from Overpass API or Protomaps, manages IndexedDB cache (L2), and flattens GeoJSON into Float64Array binary format. Reports progress back to the main thread.

2. **Render Worker** (`src/worker.ts`) — Loads the WASM module and exposes four task types: `roads` (process road geometry), `polygons` (process water/park polygons), `pois` (pass-through), and `render` (final PNG generation via tiny-skia). Multiple render worker instances are spawned for parallel processing.

### Data Flow

```
User clicks "Generate"
  → App.tsx coordinates generation
  → MapDataService.getMapData() checks L1 memory cache
  → Data Worker checks L2 IndexedDB cache
  → If miss: fetch from Overpass API → flatten to Float64Array → cache in IndexedDB + memory
  → App shards road data across N render workers
  → Workers run WASM processing in parallel (roads, water, parks, POIs)
  → Single worker runs final render with all processed data + config JSON
  → PNG returned as Uint8Array → download
```

### Three-Layer Caching

- **L1**: In-memory `Map` in `MapDataService` (instant, per-session)
- **L2**: IndexedDB via `src/db.ts` with gzip compression (~100KB per city)
- **L3**: Network fetch from Overpass API (auto-splits large areas into ≤2500km² chunks)

### Key Source Layout

- `src/App.tsx` — Main component: state management, location selection, generation orchestration
- `src/worker.ts` — Render worker (WASM bridge)
- `src/data-worker.ts` — Data worker (fetching, caching, flattening)
- `src/services/map-data.ts` — `MapDataService` singleton: L1 cache + worker communication
- `src/services/overpass-client/` — Overpass API client with rate limiting, auto-retry, area splitting
- `src/services/overpass-wrapper.ts` — Adapter between overpass-client and data-worker
- `src/services/sea-polygons.ts` — Merges ocean/sea polygons into water data
- `src/utils.ts` — GeoJSON flattening, road sharding, Protomaps fetching (legacy data fetching functions)
- `src/lib/types.ts` — Core types: `MapColors`, `MapTheme`, `Location`, themes array
- `src/lib/poster-viewport.ts` — Canonical fetch viewport calculation (ensures same radius always fetches same bbox)
- `src/components/` — React UI components (settings panels, preview, gallery, header/footer)
- `src/components/ui/` — Radix UI primitives wrapped with Tailwind
- `src/paraglide/` — Auto-generated i18n messages (do not edit directly)
- `wasm/src/` — Rust source for the WASM rendering engine (renderer, projection, data processing)
- `src/pkg/` — Compiled WASM output (generated by `build:wasm`)

### Data Source Toggle

`data-worker.ts` has a `USE_OVERPASS_CLIENT` flag (currently `true`) that switches between the new overpass-client library and legacy `utils.ts` functions. There's also a `USE_PROTOMAPS` flag (currently `false`) for Protomaps vector tile fetching.

## Tech Stack & Tooling

- **Runtime**: Bun (package manager + test runner)
- **Build**: Vite 8 with rolldown code splitting
- **Linting**: oxlint (not ESLint)
- **Formatting**: oxfmt (not Prettier)
- **Styling**: Tailwind CSS v4 (CSS-first, no `tailwind.config.js`)
- **UI**: Radix UI primitives + lucide-react icons
- **i18n**: @inlang/paraglide-js — messages defined in `project.inlang/`, compiled to `src/paraglide/`

- **WASM**: Rust compiled via wasm-pack, loaded with `vite-plugin-wasm`

## Important Patterns

- **TypedArrays for data transfer**: GeoJSON is flattened to `Float64Array` and transferred via `Transferable` objects (zero-copy) to workers. After transfer, the original buffer is detached.
- **Progress reporting**: Data Worker sends `{ type: "PROGRESS", progress, step }` messages; `MapDataService` relays them via a callback to the UI.
- **Theme system**: 20 themes defined in `src/lib/types.ts` as `MapTheme[]` with `MapColors` (background, text, road hierarchy, water, parks, POI). Users can override individual colors.
- **Location resolution**: Country → State → City cascade with fuzzy name matching and standalone-region fallback (e.g., Hong Kong as its own country entry).
- **Settings persistence**: User preferences saved to `localStorage` as `maptoposter_config` and restored on mount.
- **i18n**: Language detected from URL path → localStorage → browser preference. Paraglide compiles messages at build time.
